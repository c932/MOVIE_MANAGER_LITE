# Local Game Wall 独立迁移计划

> **For agentic workers:** 使用 executing-plans 顺序执行并验证本次迁移。

**Goal:** 将游戏墙的代码与资产全部迁至 `E:\My_Code\Local_Game_wall`，电影墙保持可独立运行。

**Architecture:** 复用已存在的独立项目副本，以当前仓库代码逐项核对；复制必要共享模块，移除电影墙仓库中的游戏专属模块。源码版使用新项目 `data/`，安装版仍使用 AppData；保留 AppData 原件及迁移冲突备份。

**Tech Stack:** Python 3.11、PyQt6、FastAPI、React、Vite、PyInstaller、MSI。

**Spec:** 用户要求迁移游戏墙全部代码和资产到指定目录；原 AGENTS.md 的数据隔离、API 契约及提交约定继续适用。

## Global Constraints

- 保存所有既有未提交修改；不写入电影墙真实 data/。
- 新旧项目不得相互依赖源码路径；共享模块各保留一份。
- 不覆盖不同内容的资产；重名资产先备份，再校验 SHA-256。
- API 前缀保持 `/api/game` 和 `/api/movie`；MSI 升级标识保持原值。
- 每轮完成修改主动提交中文 Conventional Commits。

## Review Focus

- 游戏窗口导入 ui.flow_layout 时不能隐式依赖电影模块。
- 游戏网页版根路由、类型和轮询不能残留电影 API 依赖。
- 新项目默认路径与 Excel 副本路径在任意启动目录下可用。
- 原仓库测试不能继续导入被迁走的游戏模块。
- 历版同名发行目录与个人配置不能被静默覆盖或进入 Git。
