# TMM 风格桌面刮削管理页

状态：待用户审阅。以用户提供的三张 TMM 截图为布局与工作流依据。

## 范围与目标

仅替换现有“刮削”入口打开的页面。电影墙、海报网格、电影墙详情页、系列页、排序和筛选保持原状，不改网页版。

用户选择的是独立管理页：左侧一次看清全库电影的元数据和文件状态，右侧查看选中电影；顶部进入更新媒体库、搜索刮削和编辑三个操作。延续内置完整刮削，不启动外部 TMM。

## 已确定的方向与备选

- 采用用户指定的 TMM 布局：管理主页 + 搜索刮削窗口 + 编辑窗口。
- 仅把旧三栏窗口换颜色，仍会把日常管理与候选确认混在一起，不符合此次要求。
- 将电影墙本身改成表格已由用户明确排除。

参考本地 TMM 的 `MoviePanel.java`、`MovieTableFormat.java`、`MovieInformationPanel.java`、`dialogs/MovieChooserDialog.java`、`dialogs/MovieEditorDialog.java` 的页面职责与交互组织。使用现有 PyQt6 和 Python 服务实现，不复制 Java 界面代码。

## 管理主页

```text
更新媒体库 ▾   搜索&刮削 ▾   编辑   刮削设置                关闭
─────────────────────────────────────────────────────────────
搜索电影 / 文件名…          筛选：全部 / 新增 / 待补 / 失败
┌───────────────────────────────┬─────────────────────────────┐
│ 电影状态表格                   │ 影视信息 / 演职员 / 文件    │
│ 标题 年份 上映日期 文件名 …     │                             │
│ …                              │ 海报  片名 / 原名 / 年份     │
│ …                              │ 三站评分、来源链接           │
│ …                              │ 类型 / 国家 / 导演 / 系列    │
│ …                              │ 简介、媒体参数与完整路径     │
└───────────────────────────────┴─────────────────────────────┘
电影数 / 已选数   扫描进度、当前目录、任务结果     取消任务
```

表格与右侧详情之间可拖动分隔；主表不套入整页滚动。列可排序、调宽、隐藏，允许水平滚动；标题与文件名较宽，评分与状态列紧凑。保留列设置、排序、筛选、分隔比例，重开恢复。

默认显示全部已知电影，包括新扫描未刮削视频；搜索匹配片名、原名、文件名。支持原生 Ctrl/Shift 多选、单选联动右侧详情、右键打开所在文件夹。搜索框只过滤本地，不触发网络刮削或 NAS 扫描。

列：标题、年份、上映时间、文件名、豆瓣评分、IMDb 评分、TMDB 评分、分辨率、HDR、新增、海报、字幕、刮削状态。未知值显示“—”或“未检测”，不显示成 0 分或“无”。状态使用文字/符号加颜色，不仅靠颜色区分。

### 列的数据语义

| 列 | 来源与规则 |
| --- | --- |
| 标题、年份、上映时间 | 优先 NFO；无 NFO 使用文件名建议，建议不表示匹配成功 |
| 文件名 | 视频文件名；悬停可看完整路径 |
| 三站评分 | 现有评分解析；`tmdb` / `themoviedb` 同一列和同一 Logo；缺评分显示“—” |
| 分辨率、HDR | 优先 NFO 流信息；文件名推断需标记“推测”；无依据为未知 |
| 新增 | 已发现视频但尚无有效电影元数据 NFO；保存有效元数据后移出新增筛选，独立状态列继续显示本次成功 |
| 海报 | 扫描时实际检查海报文件；离线显示最近检测状态并注明时间，不把缓存存在等同于 NAS 原图存在 |
| 字幕 | NFO 中记录的内嵌字幕轨 + 同目录同视频名的外挂字幕；支持 .srt/.ass/.ssa/.vtt/.sub/.idx；未记录内嵌轨不能断言无内嵌字幕 |
| 刮削状态 | 未刮削 / 待补信息 / 已有资料 / 处理中 / 已保存 / 失败；提示具体缺项或原因 |

不在本次新增全量视频流探测和 ffprobe 依赖。对于没有 NFO 字幕信息、也没有发现外挂字幕的视频，字幕显示“未检测到外挂 / 内嵌未知”。

### 待补筛选与保存结果

“资料完整性”和“最近操作结果”分别记录，避免保存成功被误当成所有资料齐全。实施建议：有有效 NFO，但缺片名、年份、简介、任一三站有效评分或对应来源 ID/链接，或确认原海报缺失时进入“待补”；逐项提示缺失原因。“仅缺豆瓣”继续严格使用现有豆瓣评分 + 链接双条件。独立影片没有系列、未记录字幕/分辨率/HDR、离线未检测海报，不自动判为待补。

保存成功但仍缺资料时，行状态显示“已保存 · 待补”，保留在待补筛选；无缺项则显示“已保存”。未有效刮削的视频进入新增；失败筛选按最近一次明确操作失败选择，取消不是失败。未知与不适用不混为缺失。这些为设计建议，后续可通过筛选子项选择只补评分或海报。

## 顶部操作

### 更新媒体库

主操作扫描已配置 NAS/电影目录；下拉保留选择目录扫描。只在显式点击时执行，不因打开窗口、切换筛选或保存设置自动扫描。

后台发现视频、读取 NFO 和文件状态，返回统一的管理行模型并持久化本机。底部固定显示扫描进度及可复制目录。取消/目录不可读时保留原列表，不能把失败当空库；成功后按路径合并条目，保持选择与排序。

### 搜索&刮削

选一部或多部后打开独立搜索窗口，布局参考图2：顶部完整文件路径、搜索源、搜索词、年份；左侧候选结果表（标题、年份、来源 ID），右侧候选海报与详情，下方勾选写入字段、补缺/覆盖、简介来源与海报选择。

复用 `ScrapeService`、候选匹配、跨站评分与系列补充、人工确认和 `ScrapeDraft` 保存逻辑，不在管理页再显示旧三栏完整工作台。

多选时逐部人工匹配，显示当前序号和下一部/跳过；可对选中项执行已有仅豆瓣补分操作。不批量自动把同名候选绑定到不同影片。

确认仅作用于当前影片及明确候选；保存完成才标记成功。保存失败可重试；取消不写入，取消批任务保留已保存条目。独立窗口中切换来源时默认简介来源跟随搜索源，之后允许手动切换。

### 编辑

选中一部已知电影后打开图3风格的编辑窗口，左侧表单、右侧海报，底部保存/取消。支持标题、原名、年份、上映时间、标语、简介、时长、类型、国家、系列、来源 ID/链接、三站评分及评分人数；演职员与媒体信息使用独立标签页。

本轮不增加截图中所有 TMM 专有字段（如 Wikidata、评级库、预告片下载、重命名整理）。已有未知 NFO 节点原样保留。多选时禁用普通编辑并提示只选一部，避免不明确的批量覆盖。

现有 `NFOEditorDialog` 的界面和保存链路不够直接满足需求：其旧实现同步读盘，且非统一的刮削写入事务。新编辑窗口应复用原有解析、结构化字段映射与备份/原子替换规则，在后台读写，只提交明确修改的字段。保留媒体技术参数和自定义标签，不重建整份 NFO。

未刮削视频先通过搜索匹配取得身份后编辑；不为新视频仅凭文件名自动生成匹配资料。异常 NFO 仍走已有明确备份重建流程。

## 右侧详情

只读展示选中电影的当前本地资料。海报、片名、原名、三站评分靠前，后续显示上映日期、类型、国家、片长、导演、演员、系列、简介与路径。

按需后台加载选中电影的详情，快速切换丢弃过期响应；海报复用现有高清/离线缓存，不能在线放大电影墙缩略图。无海报显示明确占位，缺信息显示缺项提示。演职员和文件页只展示当前支持的实际信息。

## 实现边界

- 保留 `MainWindow._on_scrape_saved` 及当前精确刷新电影墙的信号契约；管理页保存后发送已保存 NFO 路径。
- 新增管理页控制器、纯 Python 管理行快照以及 Qt 表模型；使用 `QTableView` + `QAbstractTableModel` + `QSortFilterProxyModel`，不为每个单元格创建 QWidget。
- `ScrapeService` 为唯一网络刮削入口；`TaskRunner` 负责后台读写、取消和代际失效；数据层不导入 Qt。
- 扩展扫描快照而非在 UI 线程再次检查 NAS；兼容旧队列，缺少新增字段按未知处理，下一次显式扫描补齐。
- 列设置及快照均使用临时文件 + `os.replace`。无在线扫描时仅恢复本地数据，不探测 NAS。
- 不覆盖现有电影墙视觉约定；设计确认后只为新的刮削管理区域扩展 `styles/style.qss` 与 `DESIGN.md`。
