# 桌面版内置电影刮削设计

日期：2026-11-14。状态：待用户审阅，尚未开始产品实现。

## 1. 目标与已确认范围

用户目前通过 tinyMediaManager 扫描新视频、搜索并匹配电影、下载海报、获取简介和评分、生成 NFO，再由本地电影墙读取。此次将该流程集成到电影墙内部，让新增电影能够直接完成刮削并入库。

用户已经确认：仅做 Windows / PyQt6 桌面版；采用电影墙内置完整刮削，而不是调用已安装的 tinyMediaManager。

必须支持：发现无 NFO 的新视频；搜索与手动匹配电影；选择并下载海报；选择 TMDB 或豆瓣简介；分别获取 TMDB、IMDb、豆瓣评分；生成现有电影墙可读的 Kodi 风格 NFO；完成后刷新电影墙。已有电影支持重新匹配和选择性补全。

其余具体行为均是本设计的建议，待用户审阅；不视为用户已经逐项指定。

## 2. 当前实现与复用点

- `utils/library_scanner.py` 只递归查找 `.nfo`，因此无法发现尚未刮削的视频。
- `ui/main_window.py` 的“刮削”和右键操作实际只对已有电影补充豆瓣评分和链接。现有文档描述的 TMM 工作流已经不对应当前代码。
- `scraper/douban_cli.py` 通过 `npx @marvae24/douban-cli` 搜索、获取详情；现有自动搜索只返回一个有评分的候选，不适合直接作为手动匹配接口。
- `parsers/nfo_writer.py` 已有无 Qt 的 XML 字段合并与原子写入能力；`parsers/nfo_parser.py` 可读取三站评分、演职员、外部 ID、简介、本地图片。
- 现有 NFO 文件名用于推断同名视频，电影墙状态及缓存也以 NFO 路径为依据。保持已有 NFO 路径稳定。
- 现有海报解析优先读取目录内 `poster.jpg`，其次读取 `<视频名>-poster.jpg`；同目录多电影时必须避免共享图片误绑定。

## 3. 方案比较与选择

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 电影墙内置数据源适配器、匹配与写入 | 完整操作都在电影墙内；能逐字段预览、选图及明确展示部分失败 | 需要维护接口适配、配置凭据、处理网络失败 |
| 电影墙调用已安装的 TMM | 可以复用 TMM 的安装及刮削配置 | 依赖外部应用及命令行能力，手动匹配和选图可能仍需切换应用 |

用户已选择第一种。继续使用现有 Python / PyQt6 栈，不引入 Java / TMM 运行环境，也不改造网页版。

## 4. 操作流程

### 4.1 发现新电影

工具栏“刮削”打开内置工作台，默认扫描已配置的电影目录，也允许选择其中一个目录。扫描在后台执行，输出“待刮削”的视频列表，不为每个视频预先创建空 NFO，也不把未确认条目混入正式电影墙。

最少支持现有解析器的 MKV、MP4、AVI、MOV、M2TS、TS，扩展名大小写不敏感。识别已有关联 NFO 的视频并标记为可更新，默认只展示缺少有效 NFO 的视频。遵守已有黑名单，额外排除 sample、预告、extras 和光盘结构内的碎片视频，避免把花絮和 BDMV 流当成电影。光盘目录、ISO、分卷合并识别不属于首版范围，需在说明中明确。

从文件名/父目录提取搜索用的片名和年份，去除常见清晰度、编码、发行组标记；推测结果始终可编辑。重叠媒体库路径去重；不可访问目录显示警告，不能被解释为用户删除了已有电影。

已存在但无法解析的 NFO 单独显示“原 NFO 损坏”，允许搜索与预览但阻止保存，提示先修复原文件；首版不把损坏文件当作不存在，也不提供一键覆盖重建，避免丢失其中不可解析的用户资料。

### 4.2 搜索并确认身份

选中视频后，提供搜索词、年份和搜索来源（TMDB / 豆瓣），展示候选的标题、原名、年份、海报和简短简介。允许改词、翻页，以及通过来源明确的 ID / TMDB、IMDb、豆瓣链接定位。

IMDb ID 使用 TMDB external find 等能力定位主电影；豆瓣链接可直接定位豆瓣条目。单独输入数字 ID 时按当前来源解释，不能猜测它同时属于多个站点。候选可包含暂无评分的新片，不能沿用旧搜索“无评分即跳过”的规则。

点击候选后才获取详情，用户确认后形成该视频的匹配草稿。自动搜索可以推荐结果，但不得在未确认匹配时写入 NFO。为降低同名、翻拍、续集串片，豆瓣匹配单独展示；优先利用一致的 IMDb ID，不能验证身份的跨站结果必须由用户确认，不静默合并。

### 4.3 预览信息与选择海报

匹配草稿显示基础信息、来源 ID、简介、海报和三项独立评分。简介下拉选择 TMDB / 豆瓣，切换即可预览；默认优先 TMDB 简体中文，缺失时提示可用语言或豆瓣内容，不把自动回退伪装成所选来源。允许保存前修改片名与简介。

海报区域列出 TMDB 可用海报（优先中文，其次无语言与英文），标明语言和尺寸；用户可选任意候选。豆瓣电影可选其详情海报。首版聚焦海报，可附带保存所选来源的背景图，但背景图不作为成功入库的必要条件。

重新匹配或切换来源时，使旧草稿、图片请求和错误提示失效；通过请求标识丢弃迟到响应，避免上一部电影的结果污染当前电影。

### 4.4 保存及刷新

新电影保存 `<视频文件名>.nfo` 与 `<视频文件名>-poster.jpg`；同目录存在多部电影时始终使用各自前缀图片，并调整本地解析优先级以避免公共 `poster.jpg` 遮盖它们。单电影目录兼容已有 `poster.jpg` / `fanart.jpg`，不批量迁移旧资产。

新流程在 NFO 写入明确的本地 `<thumb aspect="poster">视频名-poster.jpg</thumb>` 关联。用户明确选择仅保存元数据时写入空的 `<thumb aspect="poster" />`，含义为该条目尚无海报，解析器不再把目录公共海报补给它。本地显式关联优先于前缀图片与旧公共图片；不存在该元素的旧 NFO 保留原兼容回退，同时优先各自前缀图片。由此，原 A 使用公共 `poster.jpg`，新 B 仅保存元数据时，A 继续显示原图而 B 显示缺图，不改写 A 的文件。背景图采取同样的显式关联原则。远程 URL 不在本地解析时自动下载，也不得作为任意本地路径使用。

保存前展示将写入的路径和字段。新片默认写入已确认资料；旧片默认补缺，用户可明确勾选覆盖指定字段与替换海报。保留观看状态、收藏、自定义标签、用户评分、技术参数及未知 XML 节点；无法获取的数据不得清空旧值，不重命名或移动视频。

“不清空旧值”仅用于同一电影身份的补全。重新匹配确认成另一部电影时，不允许走普通补缺：预览中明确列出将替换的身份资料，包括标题/原名/年份/上映日期/简介/宣传语/片长/类型/国家/演职员/系列、三站 ID 与对应外部评分、海报及背景图。旧身份的已知字段不能混入新身份，未取得的新站点 ID/评分留空，旧图片不再关联，但不直接删除共享图片。用户须在保存确认中接受整组身份替换；用户评分、标签、观看/收藏状态、技术参数和未知 XML 节点仍保留。若用户不接受则不保存。

保存成功后重新解析 NFO、更新电影缓存与相关海报缓存，并刷新电影墙。新片需要走新增入库路径，不能只调用现有的单片更新函数。同一目标同时只能有一个保存操作，保存前重新检查磁盘文件是否已改变，有冲突则提示重新加载。

首版支持逐片确认，并批量保存已经完成身份确认的草稿；不提供无人值守的猜测匹配写盘。队列逐项显示待处理、待确认、保存中、成功、部分成功、失败；可重试失败项，取消不撤销已完成项。

## 5. 数据源与配置

| 数据 | 方案 | 凭据与失败行为 |
| --- | --- | --- |
| TMDB 搜索、详情、海报、评分、IMDb ID | 官方 v3 API，语言优先 `zh-CN`，外部 ID 和图片分别获取 | 设置页填写用户自己的 TMDB API key 或 Read Access Token；缺少凭据时明确禁用相应请求 |
| IMDb 评分 | 优先实现 OMDb，按确认后的 IMDb ID 获取 `imdbRating` 和投票数 | 设置页填写用户自己的 OMDb API key；不假定它与 TMM 凭据通用；未配置、限额或无评分时显示原因并允许后续补全 |
| 豆瓣搜索、简介、评分、海报 | 复用现有 douban-cli 的搜索/详情能力，新增完整候选映射；海报取搜索结果的 `cover` | 需要 Node / npx；若被限流、要求登录或字段缺失则明确显示，不承诺无凭据稳定访问 |

IMDb 评分必须具有真实的 IMDb 来源；TMDB 的评分和外部 IMDb ID 不能当作 IMDb 评分。三站分数保存为独立来源，合法值为 0–10；无评分、N/A、非有限数值不写作 0 分。只有投票数有效时才写入对应票数。

已只读检查 npm 发布的 douban-cli 0.7.0 源码：`searchMovies` 返回 `id/title/year/type/rating/rating_count/cover` 等字段，电影详情返回 `summary`，但不返回海报和 IMDb ID。适配层须保留搜索候选的 `cover`；直接输入豆瓣链接时，如需海报可按返回片名搜索并严格以豆瓣 ID 找回对应 `cover`，未找到则明确缺失，不取另一条目的图片。该版本的跨站豆瓣合并必须由用户确认，不能假定能按 IMDb ID 自动校验。区分 `movie/tv`，过滤剧集。当前 Windows 的 Node 为 v24.13.0，满足该包要求的 >=22.13.0。

默认不抓取 IMDb 网页作为隐式后备，也不下载整份 IMDb 数据集；避免引入不确定的网页反爬与大文件依赖。用户如要求无 OMDb key 的 IMDb 方案，需要单独验证可用来源并更新设计。

刮削设置与现有路径设置分开保存，遵循 `MML_DATA_DIR` 及安装版数据路径；JSON 采用临时文件和 `os.replace`。凭据输入掩码、日志脱敏、不提交真实配置。首版明确为本机配置文件保存，不宣称已加密。支持连接测试、请求超时和可配置 HTTP(S) 代理；代理作用限于新刮削请求，douban-cli 是否支持代理需验证并如实显示。

部分失败不会伪装为“三站全部成功”。例如 TMDB 和海报已成功、豆瓣受限：显示缺失原因，允许用户保存已取得资料，之后仅补豆瓣；未下载到海报时须明确选择是否仅保存元数据。

## 6. 内部结构与后台任务

领域层使用纯 Python 模块组织：视频发现/名称推断、标准化候选与详情、TMDB / OMDb / 豆瓣适配、字段合并、资产下载与 NFO 提交。复用 `parsers/nfo_writer.py`，新增 NFO 通过 `<movie>` 树和同一字段处理器写入，不复制一套 XML 拼接逻辑。旧豆瓣评分补全操作保持兼容。

PyQt6 层新增独立刮削工作台及设置对话框，工具栏打开新流程，电影右键提供“重新匹配/刮削”；原豆瓣评分补全保留为快捷操作。布局延续现有中文界面风格，长路径可查看全文，小屏窗口内部滚动，主要按钮始终可达。

网络、扫描、图片下载、写盘均使用后台 worker，通过信号汇报进度和结果；主线程负责控件和 QPixmap。明确线程的引用、结束清理和关闭窗口行为：取消后不派发新任务，等待有界的请求结束，不强行 terminate 线程，也不允许后台信号访问已经销毁的控件。

HTTP 错误区分认证失败、无匹配、请求超时、限流、站点受限、响应格式变化。429 等瞬态错误采用有上限退避；批量豆瓣请求串行限速。图片下载限制响应大小、验证内容确为可解码图片，只有完整有效图片才替换旧海报；候选缩略图仅作为临时缓存。

NFO 与图片各自采用同目录临时文件及原子替换，但不声称多个文件拥有文件系统事务。先准备并校验所有产物，提交前备份将覆盖的文件，再替换图片、最后提交 NFO；进程内异常尝试回滚并记录失败路径。进程崩溃或 NAS 中断时保留可恢复备份并报告残留状态。提交过程中延期取消至当前电影结束，避免主动制造半写入。重复保存相同草稿不重复产生电影记录。

## 7. 边界与不做的内容

首版仅面向电影、桌面本地及可写 NAS 目录；不做电视剧刮削、视频重命名/整理、字幕下载、自动删除、TMM 配置迁移或网页版 API/UI。蓝光/ISO/分卷自动组装不列入首版验收。

不修改真实媒体库进行自动测试；不会为了验证主动覆盖用户已有 NFO 或图片。网络与凭据依赖是可见的功能状态，不能用 mock 通过代替真实联网验收。

## 8. 验证与验收

自动测试全部使用临时 `MML_DATA_DIR`，重置 ConfigManager 单例。覆盖新片发现、大小写扩展名、黑名单、重叠路径、多视频目录、有效/无效 NFO、名称推断；API 的候选列表/详情映射、无评分新片、非成功返回与跨站身份冲突；字段合并、保留未知 XML 与用户数据、三站评分独立写入；图片损坏/超限、保存中途失败、回滚、取消及并发冲突。

Qt 验证重点是后台请求期间界面可操作、切换电影不会串结果、取消/关闭不会崩溃，以及新增入库和换海报后显示最新内容。截图检查至少覆盖普通桌面和较小窗口。检查无 Qt 的领域模块导入约束，运行仓库要求的 Python 测试；此次不改前端，不以网页构建充当桌面验证。

联网验收需配置用户有效的 TMDB / OMDb 凭据。选择临时测试目录内的一部有三站数据的电影、一个有重名/翻拍候选的电影以及一个缺少部分评分的新片，验证：无 NFO 视频被发现；搜索并手动确认正确条目；切换中文简介和海报；真实获取可用的三站分数；保存后用现有解析器及电影墙重新打开；无凭据、豆瓣受限时展示准确状态。真实来源未验证的部分在交付中逐项注明。

## 9. 留给实现者的决定

具体模块命名、worker 调度粒度、候选分页与缓存容量、退避时长、备份命名可以按现有代码选择。实现前核对 douban-cli 的实际字段与运行环境；如发现其不支持目标能力，先给出证据及替代方案，不能把缺失功能标为完成。新依赖与打包收集项按实际需要最小化，并验证 Windows Python 3.11 打包路径。
